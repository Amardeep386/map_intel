What changed

How this refines the addendum 3 roadmap

Addendum 3 is a strong base and most of it is kept. These are the changes, each with the reason.

Collection is ours to build

The spec assumed crawlers were an upstream service. Mirethos has none today, so collectors, validation and source health are planned in Phase 2.

Without it, V2 has nothing to cleanse.

Evidence is captured at collection

Screenshots and HTML are taken when the price is seen, not when a violation or report is produced later.

Pages change within hours; a late capture proves nothing.

A Phase 0 was added

The current portal is front-end only with mock data. It needs a backend skeleton, bug fixes and the build-vs-buy decision before V1 starts.

Addendum 3 itself says two decisions must precede V1.

Basic email alerts moved into Phase 3

New violating seller, severe depth and source-degraded alerts ship with the pilot; Slack, webhooks and the full rule set stay in Phase 4.

The company doc's MVP includes email alerts.

Audit log and policy versioning moved earlier

The audit log starts in Phase 1 and policy documents are versioned in Phase 2, not V5.

Rules, letters and evidence cite the policy; audit can't be retrofitted.

Pricing split out cleanly

"MAP & Pricing" becomes "MAP Policies". Competitive price comparison, price index and competitor sets move to Pricing Intel, but the observation store is designed to serve both.

Two separate portals, one shared data core.

One status model for violations and cases

Violation statuses (Open, Needs review, Under notice, Authorised promo, Resolved, Dismissed) are kept separate from case states (Open → Notice sent → … → Recurred).

The two source docs used overlapping, conflicting lists.

Deferred until after MAP Intel

Natural-language AI search, test buys, deep seller identity resolution and image-based discovery at scale.

None is needed for a pilot brand to trust the data.
Portal changes

Same UI, reorganised around the workflow

The shell stays: sidebar, client switcher with brand accent, cards, tables, drawers, light/dark theme. The navigation gains group labels (Monitor, Catalogue, Collection, Deliver, Admin). The prototype tags each item New or Updated.

Data architecture

Nine domains, one shared core

Observations are stored separately from master data, so historical truth survives when products, MAP values, seller classifications or rules change.

Append-only factsObservations, MAP prices, seller classifications and violations are never edited. Corrections are new records.
Effective-dated everythingMAP, promo windows, classification, rules and policy documents each carry from/to dates. A verdict stores the versions it used.
Hard tenant boundaryEvery account-owned row carries account_id, enforced with Postgres row-level security. Only the source catalogue is shared.

Decisions needed

Settle these in Phase 0

Each one changes what gets built. A recommendation is given, but these are your calls.

1 · Build or buy collection?

Open across the spec and all three addenda.

Recommended: build in-house for 5–7 launch sources (Amazon, Walmart, Best Buy, eBay, Home Depot, Target), with a data vendor as a fallback for hard sources. It is the core of the shared data layer and of the margins.

2 · Who is the pilot brand?

LG, Philips, Kawasaki and Citizen appear in the prototype.

Recommended: one brand, US only, 50–300 SKUs, with an existing MAP policy PDF and a spreadsheet of MAP prices. That sizes Phase 2 realistically.

3 · Brand users in the pilot, or reports only?

Spec open question 3.

Recommended: reports and evidence links first (Phase 3), read-only brand login in Phase 4. Keeps permissions work out of the critical path.

4 · What volume do we size for?

Listings per account, observations per day, accounts at launch.

Needed: a rough number decides how the observation table is partitioned and what collection costs per month.

5 · Legal boundary

Collection methods, site terms, and wording of notices.

Recommended: a short review with counsel before Phase 2. The product records observations and supports the brand's enforcement; it does not make legal determinations.

6 · Missing reference material

The spec PDFs note that the "cyber analyst" recordings and the Case Management, Price Grid and Visualizations screens were never seen.

If available: share them before Phase 4. The Case Management screen could change how enforcement is designed.
